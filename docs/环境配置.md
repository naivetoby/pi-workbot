# 环境配置

工作区使用 Pi `1.5.2` 原生配置。配置随镜像分发，凭证由 GitLab environment 或独立部署的 `.env` 在运行时提供。

## 目录与初始化

| 路径                                              | 内容                                                       |
| ------------------------------------------------- | ---------------------------------------------------------- |
| `configs/chat/`                                   | chat 的 `settings.json`、`AGENTS.md`                       |
| `configs/code/`                                   | code 的 `settings.json`、`AGENTS.md`                       |
| `configs/<角色>/npm/package.json`、`npm/bun.lock` | 角色插件安装清单与传递依赖锁定                             |
| `configs/shared/`                                 | 共用的 `models.json`、`mcp.json`、Skills、来源记录和许可证 |
| `configs/projects.json`                           | 启动时预拉取的项目清单                                     |

首次初始化先复制角色目录，再从共享目录补充缺少的文件，同名文件以角色目录为准，按完整文件选取。运行时 Pi 目录由 `PI_CODING_AGENT_DIR` 指定，镜像默认为 `/runtime/pi`。

`configs/projects.json` 默认 `[]`，不预拉取项目。中转站通过 `OPENAI_RELAY_BASE_URL`（含 `/v1`）和 `OPENAI_RELAY_API_KEY` 配置。

Pi 不原生展开 `baseUrl`，Workbot 首次初始化时只替换 `openai-relay` 的地址占位；地址为空时不启用该 provider，不影响 DeepSeek。修改地址变量需重新创建容器；字面端点及初始化后的在线修改保持不变，密钥仍由 Pi 解析。

初始化完成后保留在线修改。更新镜像默认配置需要修改 `configs/`、重新构建并创建新容器；当前容器中的设置可通过 Pi Web 调整。在线试验到镜像发布的流程见 [云端环境迭代](环境迭代.md)。

## 模型与插件

| 设置                   | chat                   | code               |
| ---------------------- | ---------------------- | ------------------ |
| `defaultProvider`      | `openai-relay`         | `deepseek`         |
| `defaultModel`         | `gpt-6.1-sol`          | `deepseek-flash`   |
| `defaultThinkingLevel` | `high`                 | `high`             |
| 默认模型凭证           | `OPENAI_RELAY_API_KEY` | `DEEPSEEK_API_KEY` |

当前默认值以 [chat settings](../configs/chat/settings.json)、[code settings](../configs/code/settings.json) 为准；修改默认值时同步维护本表，不在其他文档重复维护模型清单。自定义端点和可选模型以 [models.json](../configs/shared/models.json) 为准。思考档位按 Pi 和模型的实际支持生效，已保存会话使用自身的模型选择。

两角色均在 settings 中声明以下插件的固定版本，具体版本只在配置和锁文件中维护；Pi 的在线包操作通过 `"npmCommand": ["bun"]` 使用 Bun：

| 插件                    | 用途                       |
| ----------------------- | -------------------------- |
| `pi-web-access`         | 联网搜索与抓取             |
| `pi-subagents`          | 用户明确授权后的子代理任务 |
| `@juicesharp/rpiv-todo` | 任务跟踪                   |
| `pi-lens`               | 代码导航、诊断和结构化搜索 |

共享 Skills 包含固定提交的 antfu/skills 技能和本地 `git-commit`，来源见 [skills-source.json](../configs/shared/skills-source.json)。插件自带的资源由 Pi 加载。GitLab 操作遵循角色约定，使用 glab。

## Pi 配置文件

按需将原生文件放入角色目录或共享目录：

| 文件或目录                           | 用途                                               |
| ------------------------------------ | -------------------------------------------------- |
| `settings.json`                      | 默认模型、思考强度、插件与资源路径                 |
| `models.json`                        | 模型端点、自定义模型和能力覆盖                     |
| `mcp.json`                           | MCP 服务、凭证引用和工具暴露方式；当前服务列表为空 |
| `AGENTS.md`、`AGENTS.override.md`    | 研发工作约定                                       |
| `SYSTEM.md`、`APPEND_SYSTEM.md`      | 系统提示词替换或追加                               |
| `extensions/`、`skills/`、`prompts/` | 扩展、Skills、提示词模板                           |
| `keybindings.json`、`themes/`        | TUI 快捷键和主题                                   |
| `auth.json`                          | 运行时提供的 Pi 凭证文件，应保持私密               |

项目级 `.pi/` 按 Pi 的信任和优先级规则加载。两角色当前设置 `defaultProjectTrust: "always"`，维护者应审核授权仓库的配置和扩展。

相对资源路径以对应 Pi 配置目录为基准。命令、语言服务器、绝对路径和外部服务需要在容器内可用，环境变量引用按 Pi 或对应插件支持的字段解析。例如：

- `models.json`：`"apiKey": "${RELAY_API_KEY}"`。
- MCP HTTP headers：`"Authorization": "Bearer ${MCP_TOKEN}"`。

## IM 配置

飞书和企业微信按环境凭证自动启用，支持单独或同时接入：

| 渠道     | 所需环境变量                         |
| -------- | ------------------------------------ |
| 飞书     | `FEISHU_APP_ID`、`FEISHU_APP_SECRET` |
| 企业微信 | `WECOM_BOT_ID`、`WECOM_BOT_SECRET`   |

每组两项均非空时启用，留空时停用，只填一项会提示并跳过该渠道。仅使用 Web 时两组均留空；修改后重新创建容器。

`configs/chat/settings.json` 的 `pi-channels.adapters` 配置渠道参数，两种渠道均使用 WebSocket：

```json
{
  "feishu": {
    "type": "feishu",
    "appId": "${FEISHU_APP_ID}",
    "appSecret": "${FEISHU_APP_SECRET}",
    "eventMode": "websocket",
    "respondToMentionsOnly": true,
    "allowedSenderIds": ["ou_replace_me"]
  },
  "wecom": {
    "type": "wecom",
    "botId": "${WECOM_BOT_ID}",
    "secret": "${WECOM_BOT_SECRET}",
    "eventMode": "websocket",
    "mentionName": "Pi Workbot",
    "allowedSenderIds": ["replace_me"]
  }
}
```

示例中的用户 ID 需替换为实际值。仓库中的 `allowedSenderIds` 默认为空，表示允许所有发送者；可结合应用可见范围配置准入。图片、附件、队列和会话命令由 pi-channels 处理。

## 运行参数与凭证

| 变量                          | 默认值或来源                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| `PI_CODING_AGENT_DIR`         | 镜像为 `/runtime/pi`；本地为 `.runtime/<角色>/pi`                                  |
| `WORKBOT_WORKSPACE`           | 项目工作区和 Web 默认目录；镜像为 `/workspace`，本地为 `.runtime/<角色>/workspace` |
| `WORKBOT_PROJECTS_FILE`       | 仓库 `configs/projects.json`，镜像内为 `/opt/workbot/configs/projects.json`        |
| `WORKBOT_CONTROL_PROJECT`     | chat Compose 使用 `CI_PROJECT_PATH`                                                |
| `GITLAB_HOST`、`GITLAB_TOKEN` | GitLab 实例与服务账号令牌                                                          |
| `WORKBOT_CODE_REF`            | 默认控制项目的默认分支                                                             |

模型、IM、Web 的变量和 Runner 配置见 [使用说明](使用.md#3-配置运行变量)。chat/code 分别使用 GitLab `chat` / `code` environment。新增 chat 凭证引用时，同步补充 Compose `environment`。

Pi 进程及其工具可以访问容器内提供的文件、凭证和网络。维护者按角色提供必要凭证，通过 GitLab 权限、IM 准入、Web 认证和部署网络控制访问范围；工具策略按需通过 Pi 插件配置。

## 构建与资产检查

构建时，`prepare:pi` 核对 settings 中的 npm 来源与角色 `npm/package.json`，使用 `npm/bun.lock` 冻结安装，跳过安装脚本和宿主提供的 peer 依赖；再由 Pi 原生包管理器解析资源，不执行扩展工厂，也不隐式补装缺失来源。安装结果随角色配置进入镜像，初始化时复制到运行目录。

普通构建不会更新锁文件。新增、删除或升级 npm 插件时，先改角色 settings，再显式更新对应角色的安装清单和锁文件：

```sh
bun run prepare:pi configs/chat --update-lock
bun run prepare:pi configs/code --update-lock
bun run check:assets
```

只更新受影响角色即可；检查并提交 `settings.json`、`npm/package.json` 和 `npm/bun.lock`，不提交 `npm/node_modules/`。两个角色独立锁定，允许后续分别演进。其他来源继续遵循 Pi 规则，但镜像准备不会下载缺失的 git/local 来源，需要先将其固定并准备为构建资产。

角色资产 smoke 在临时 HOME、空项目和隔离凭证环境中检查资源加载；Linux 角色构建使用自身 Pi 与锁定插件执行 `smoke:lens`，验证预装工具、LSP 诊断和会话退出。真实凭证、模型与业务链路在部署环境验收。准备和检查命令见 [使用说明](使用.md#本地开发)。
