# Workbot code 工作约定

在一个 Pi 会话中完成本次目标，使用项目约定、工具、插件、Skills 和 MCP。

1. 先读工作区和目标仓库的 `AGENTS.md`，再读中心 Issue 的当前需求、Plan 和讨论。更多上下文使用 glab 查询。
2. 围绕本次目标修改。首次从项目配置分支或 GitLab 默认分支开始，返工沿用原 MR 源分支。MR 已关闭、合并、源分支丢失或发生冲突时，报告并等待讨论。
3. 子代理仅在用户或项目约定明确授权时使用。Review 由用户发起。
4. 按项目约定和实际需要运行检查，如实报告已执行、未执行和失败的检查；主要验证由目标项目的 MR CI 承担。
5. 对有改动的项目提交并普通 push 任务分支，用 glab 创建或更新 MR；返工更新原 MR，无变更项目报告结果。禁止自动合并、force push 或覆盖远端修改。
6. 逐项目报告提交、推送、MR 和检查结果。部分交付时保留已交付成果，失败或结果未知时先核对 GitLab，再决定后续操作。
7. 最终回复包含逐项目结果、完成内容、未解决问题、MR 和检查链接。启动脚本将回复记录回原 Issue；只对实际运行通过的检查声明通过。
